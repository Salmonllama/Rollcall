# Step 2: Run the install command

**What you're doing:** installing Rollcall on your server with one command, then confirming the portal loads over HTTPS.

Before you start, finish the [prerequisites checklist](01-prerequisites.md). The install takes about 5 minutes, plus the time to download the container images.

## Run the installer

Sign in to the server and run:

```bash
curl -fsSL https://github.com/Salmonllama/Rollcall/releases/latest/download/install.sh | sudo bash
```

The installer asks three things:

1. **Hostname:** the name technicians will open, for example `rollcall.contoso.com`.
2. **Certificate type:** Let's Encrypt, your own certificate files, or a local certificate for test machines.
3. **Details for that certificate type:** an email address for Let's Encrypt expiry notices, or the paths to your certificate and key files.

Then it works through each step on its own and prints a ✓ or ✕ for each one.

### Install without questions

For automation, pass every answer as an option and add `--yes`. Pick the line for your certificate type:

```bash
curl -fsSL https://github.com/Salmonllama/Rollcall/releases/latest/download/install.sh | sudo bash -s -- --hostname rollcall.contoso.com --tls letsencrypt --email it@contoso.com --yes
```

```bash
curl -fsSL https://github.com/Salmonllama/Rollcall/releases/latest/download/install.sh | sudo bash -s -- --hostname rollcall.contoso.com --tls custom --cert /root/rollcall.pem --key /root/rollcall.key --yes
```

```bash
curl -fsSL https://github.com/Salmonllama/Rollcall/releases/latest/download/install.sh | sudo bash -s -- --hostname rollcall.test --tls internal --yes
```

Run `sudo bash /opt/rollcall/install.sh install --help` after installing to see every option.

## Expected result

The installer ends like this:

```text
✓ Rollcall 1.0.0 is installed.
  Setup token: K32CVYDXFJJRLRHZN4BXK6LRVHG35OAVKZ3QJ6Q
  The setup wizard asks for this token. It is also in /opt/rollcall/.env.

https://rollcall.contoso.com

Open https://rollcall.contoso.com to finish setup.
```

Keep the setup token private. Anyone who has it before setup is finished can connect their own tenant to your Rollcall.

The installer writes everything to `/opt/rollcall`:

| File | What it holds |
| --- | --- |
| `.env` | Generated secrets and settings, readable by root only. Losing `ROLLCALL_MASTER_KEY` makes encrypted data unreadable, so include this file in your server backups or keep Rollcall backups (step 9). |
| `docker-compose.yml`, `Caddyfile` | The rendered configuration. `install.sh update` rewrites them, so don't edit them by hand. |
| `install.sh` | A copy of the installer, for the commands in [Installer commands](../admin/installer-commands.md). |
| `local-ca.crt` | Only with `--tls internal`: the certificate to trust on computers that open Rollcall. |

The install log is `/var/log/rollcall-install.log`.

### If a step fails

The installer stops at the failed step and prints the likely cause and the next command to run, for example:

```text
✕ Port 443 is already in use.
  Likely cause: another web server, such as nginx or Apache, is running on this host.
  Next: find it with "sudo ss -ltnp 'sport = :443'", stop it, then run the installer again.
```

Fix the cause and run the same install command again. Secrets generated by the failed attempt are kept, so a rerun picks up where it stopped.

Running the install command on a server where Rollcall is already installed changes nothing. It tells you to run `install.sh update` instead.

### Using a local certificate

With `--tls internal`, Caddy issues a certificate from its own local authority. To open Rollcall without a browser warning:

1. Copy `/opt/rollcall/local-ca.crt` to each computer that will open Rollcall, and add it to that computer's trusted root certificates.
2. Point the hostname at the server, in DNS or in that computer's hosts file.

Use this option for test machines only. Production installs should use Let's Encrypt or your own certificate.

## Check it worked

Run on the server:

```bash
sudo bash /opt/rollcall/install.sh status
```

Expected result: four services (`app`, `db`, `proxy`, and `worker`), each `Up ... (healthy)`, followed by:

```text
✓ Rollcall 1.0.0 is ready at https://rollcall.contoso.com.
```

Then run this from a technician's computer, replacing the hostname:

```bash
curl -fsS https://rollcall.contoso.com/readyz
```

Expected result:

```json
{"db":"ok","migrations":"current","worker":"ok"}
```

Finally, open `https://rollcall.contoso.com` in a browser. You should see the Rollcall page with no certificate warning, unless you used a local certificate you haven't trusted yet.

If `status` shows a service that isn't healthy, run `sudo bash /opt/rollcall/install.sh logs app` (or `proxy`, `worker`, or `db`) to see why.
