# Rollcall v1.0.0 Live-Environment Verification Walkthrough

Use this sign-off checklist to validate Rollcall v1.0.0 in a real environment (clean Linux VM + live Microsoft 365 / Entra ID developer or staging tenant + Windows Server Active Directory lab for hybrid) before tagging `v1.0.0`.

## 1. Host installation & TLS (Linux VM)

- [ ] Provision a clean Ubuntu 24.04 LTS (or Debian 12 / Rocky 9) VM with 2 vCPU / 4 GB RAM and ports 80/443 reachable.
- [ ] Run `install.sh` with `--tls letsencrypt` (or `--tls custom` with an internal CA cert) and verify total install completes cleanly with valid HTTPS padlock.
- [ ] Confirm `/opt/rollcall/.env` is `0600 root:root` and PostgreSQL port `5432` is NOT exposed on the host (`ss -ltnp`).
- [ ] Verify `GET https://<host>/healthz` returns `200 OK` and `sudo bash /opt/rollcall/install.sh status` reports `db: ok`, `migrations: current`, `worker: ok`.
- [ ] Verify security headers (`Content-Security-Policy`, `X-Frame-Options: DENY`, `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`) on HTTPS responses.

## 2. Setup wizard, RSA 3072 app registration & OIDC sign-in

- [ ] Open `https://<host>`, enter `ROLLCALL_SETUP_TOKEN`, and verify invalid tokens are rejected and rate-limited.
- [ ] Generate the RSA 3072 certificate, download the `.cer`, and run the generated PowerShell registration script against your live Entra tenant (verify NO client secret is created on the app registration).
- [ ] Grant admin consent for required Microsoft Graph application permissions and `Exchange.ManageAsApp`, and assign **Exchange Administrator**, **User Administrator**, and **Authentication Administrator** directory roles to the service principal.
- [ ] Click **Validate connection** and verify every permission and directory role reports **Granted** and organization name matches your live tenant.
- [ ] Complete setup by signing in via live Entra ID OIDC (`openid`, `profile`, `email`). Verify `/setup` is permanently locked (`404` / redirect) afterward.
- [ ] Verify an uninvited Entra user from the same tenant receives `403` and an account from a *different* Entra tenant is rejected by single-tenant issuer validation.
- [ ] Invite a second **Admin**, an **Approver**, a **Technician**, and an **Auditor** in **Admin › Team**; verify server-side role boundaries (Technician cannot access `/api/admin/*` or `/api/ca/*`; Auditor cannot mutate).

## 3. Directory views & cloud management (live Graph + Exchange Online)

- [ ] Confirm **Users**, **Groups**, **Licenses**, and **Dashboard** load live data from your tenant with pagination and filters working.
- [ ] **Attributes (single & bulk):** Edit job title/department on a test user (and 3+ test users in bulk), inspect Change Preview, confirm, and verify changes in Entra admin center.
- [ ] **Drift detection:** Preview a change, modify the same attribute directly in Entra admin center before confirming/executing, and verify Rollcall pauses the run in **Needs attention** without overwriting.
- [ ] **Groups & Distribution Lists:** Add/remove a test user on an Entra Security group, a Microsoft 365 group, and an Exchange Online Distribution List; confirm Exchange Online PowerShell (`ExchangeOnlineManagement` 3.10.1) downloads, passes SHA-256 tree hash verification, and executes cleanly.
- [ ] **Licenses:** Assign and remove a license SKU with a disabled service plan; confirm group-inherited licenses are shown read-only with source group attribution.
- [ ] **MFA, TAP, Password reset & Sessions:** Issue a Temporary Access Pass (TAP) for a test user, view it once (verify second view returns `410 Gone`), confirm the TAP works at `https://mysignins.microsoft.com`, verify the TAP value does NOT appear in PostgreSQL or container logs, revoke sessions, and reset password.

## 4. Role templates, cloud onboarding & Welcome Pack PDF

- [ ] Create a live **Role Template** under **Admin › Role templates**; verify saving fails if an invalid group or SKU is referenced.
- [ ] Onboard a brand-new test user immediately using the template; verify collision detection blocks a duplicate UPN (and does NOT invent `user2`).
- [ ] Download the **Welcome Pack PDF** with default branding AND with **Hide Rollcall branding** enabled; confirm both render cleanly and neither contains the TAP or temporary password.
- [ ] Test a **Scheduled onboarding** (future start time): verify Phase 1 creates the user with sign-in blocked, and Phase 2 automatically unblocks sign-in at the scheduled timestamp.

## 5. Offboarding, OneDrive handover & Restore

- [ ] Run **Offboarding** on the test user with **Convert mailbox to shared**, **Hide from GAL**, **Out-of-office reply**, **OneDrive handover to manager**, **Remove groups**, and **Remove direct licenses**.
- [ ] Confirm typed UPN confirmation and Approver sign-off are required (and self-approval is rejected).
- [ ] Verify in Exchange Online and Entra ID that:
  - Sign-in is blocked and sessions are revoked.
  - Mailbox converted to **Shared** strictly *before* license removal.
  - Manager received OneDrive access and a timed reversal is scheduled.
  - Direct licenses and group memberships were removed.
- [ ] Click **Restore user** on the completed offboarding run and verify sign-in, license, groups, and regular mailbox type restore cleanly.

## 6. Conditional Access safety rails (Admin-only)

- [ ] Register your tenant's emergency access (break-glass) account(s) in **Admin › Conditional Access**.
- [ ] Verify Rollcall **hard-blocks** removing a break-glass account from an enabled CA policy's exclusions.
- [ ] Add a **timed temporary exclusion** (for example 15 minutes) for a test user on a test/report-only CA policy; verify typed policy name confirmation + second-admin approval, verify Graph only patched `conditions.users` (grant controls/apps untouched), and verify automatic removal after the timer expires.

## 7. Hybrid Active Directory agent (Windows Server lab)

- [ ] Run `New-RollcallGmsa.ps1` with an explicit `-AllowedOUs` list on a domain-joined lab server.
- [ ] Generate a single-use enrollment token in **Admin › AD Agents** and run `install-agent.ps1` under the gMSA.
- [ ] Confirm outbound-only HTTPS (no inbound ports opened on the Windows host), agent appears **Online** in **Admin › AD Agents**, and `agent-key.bin` is DPAPI-protected.
- [ ] Test a **Hybrid user attribute edit**, **Hybrid group add/remove**, **Hybrid onboarding** (AD create -> Entra Connect delta sync -> cloud license/mailbox), and **Hybrid offboarding** (AD disable + move to Disabled OU + cloud/Exchange steps).
- [ ] Attempt to edit an AD user **outside** `AllowedOUs` and confirm `OuScopeGuard` rejects it before any LDAP write.
- [ ] Stop the `RollcallAgent` service, submit a hybrid run, confirm it waits in **Waiting for AD agent**, restart the service, and confirm it automatically resumes and succeeds.
- [ ] Test **Revoke agent** in **Admin › AD Agents** and confirm the agent immediately receives `401 Unauthorized`.

## 8. Operations, recovery & security checks

- [ ] **Guided cert rotation:** Run **Admin › Connections › Start certificate rotation**, upload the new `.cer` to Entra ID, click **Verify & activate**, confirm live Graph & Exchange calls work, click **Retire previous certificate**, and delete the old cert from Entra ID.
- [ ] **Audit log integrity & export:** Click **Verify hash chain** (passes) and **Export CSV** (opens cleanly in Excel with UTF-8 BOM and ISO 8601 timestamps).
- [ ] **Backup & restore drill:** Run `sudo bash /opt/rollcall/install.sh backup`, confirm **Admin › Health** updates **Last backup**, then test restoring the archive onto a second clean VM (`install.sh restore <archive>`).
- [ ] **Master key rotation:** Run `sudo bash /opt/rollcall/install.sh rotate-master-key`, confirm services restart healthy and live Graph/Exchange calls continue working.
- [ ] **Admin lockout recovery:** Run `sudo bash /opt/rollcall/install.sh admin-reset <upn>`, confirm the user regains Admin on next sign-in and an audit event is recorded.
- [ ] **Browser & accessibility spot check:** Test light mode, dark mode, keyboard-only navigation, and mobile viewport across Dashboard, Users, Onboarding, Offboarding, Approvals, and Admin pages.
